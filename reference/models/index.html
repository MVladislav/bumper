    Model Compatibility

    This page tracks Ecovacs models reported to work with Bumper, known limitations, and reports that still need clarification.

    Model names, classid values, and model values use bumper/web/static_api/productIotMap.json. Match a robot by its classid when possible; marketing names can cover several variants. Reports come from project discussions and issues. A missing model has not been reported here; that does not mean it is unsupported.

    Reported working

    These models have been reported to work with Bumper or its previous fork. The reports do not guarantee current behavior, every feature, or official app support.

    Note: The current XMPP implementation appears to be broken, so models that worked with earlier versions may no longer work.

    Reporting a model

    When opening a discussion, include the classid, model, firmware version, transport, and whether the official app or only a client can control the robot. Logs with DEBUG_BUMPER_LEVEL=DEBUG are useful when available.

    Troubleshooting notes

    The usual reasons, in the order they are worth checking:

    1. Certificate pinning. The robot ignores the CA and trusts only the certificate it shipped with. Check the per-device guides: bot, GOAT, app.
    2. Key type. Some robots only offer RSA in their client hello while Bumper generates an EC key. Set CERT_KEY_TYPE=rsa and CERT_RSA_KEY_SIZE=2048.
    3. Transport. Older models speak XMPP, newer ones MQTT, the newest ones NGIoT. A model on the wrong transport connects and then answers nothing.
    4. DNS. A robot that still reaches the Ecovacs cloud is not talking to Bumper. See DNS Setup.
